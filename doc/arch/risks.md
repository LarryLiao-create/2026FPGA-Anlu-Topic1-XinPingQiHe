# 风险与决策记录 —— 图片切换淡入淡出转场

工程：med_screen（安路 EG4S20BG256B）

## 0. 与用户原始方案的三处偏离（最重要，需用户知悉）

| ID | 用户原方案 | 本设计 | 原因 |
|---|---|---|---|
| R-01 | 任务2/任务3：`read_len` 改 640，`read_req` 每行触发（逐行读） | 既有读通路**恢复“每帧整帧连续读”**（`read_len=307200`，每帧一次 `read_req`） | 现版本逐行读但**读地址是固定基址**（`frame_fifo_read` 无 `y*640` 行偏移），480 行全部读第 0 行；且 `rd_toggle` 令相邻行交替取自显示BUF与BUF2，造成隔行撕裂。用户已确认“上板显示确实不对”。逐行语义改由新的取数引擎在 mem 域承担，既有通路无需逐行 |
| R-02 | 切换前把当前帧**整帧复制到 BUF2**，复制期 `freeze` 黑屏 1~2 帧 | **不复制、不冻结**：`old` 图就是“上一帧正在显示的那块缓冲”，它在写新图期间未被改动，天然完好 | 整帧复制需 307200 词读写（约 2.4 ms）+ 冻结，代价大且会黑屏；而 BUF(disp^1) 在转场开始时仍持有旧图，直接读它即可 |
| R-03 | 任务1：恢复 `rd_toggle`（`rd_addr_idx_sel = rd_toggle ? 2'd2 : read_addr_index_d1`） | **移除 `rd_toggle`** | `rd_toggle` 正是隔行撕裂的成因；转场不再依赖 BUF2 |

> **BUF2_ADDR 本次不使用**，定义保留（`interface_contract.yaml` 第 9 节、帧缓冲映射仍列出）。若后续希望用三缓冲轮换（写目标永不为 old），可在本架构上平滑扩展。

## 1. 高风险项

| ID | 风险 | 影响 | 缓解 / 验证 |
|---|---|---|---|
| R-04 | **转场启动瞬间的启动竞态**：`disp_buf_idx` 变化（= 转场起点）在 sd 域产生，`xfd_busy` 需经 sd→video→sd 两次同步才能抵达 `sd_card_bmp`。若此窗口内恰好有新的写图任务启动，会写入 `BUF(disp^1)`（正在参与混合的 old 图） | 该次转场出现错误画面 | ①`auto_cnt` 在每次 load 启动时清零，自动轮播下最快也要 1 s 才会再次触发；②人工按键落在约 150 ns 窗口内的概率可忽略。**若实测到偶发异常**，加固方案：在 `sd_card_bmp` 内加“commit 后 N 个时钟的冷却”（N 取 ms 量级，用户不可见），或在 mem 域判 `write_addr_index == old_idx` 时抑制写突发 |
| R-05 | **单行取数时序预算**：每行需读 2×640=1280 词，@125 MHz 需 ≥10.2 µs（纯数据），加 SDRAM 行激活/刷新/突发首字节开销后按 60% 效率估约 17 µs | 若超出 32 µs 行周期，下一行首段读到旧帧残行（可见接缝） | 预留 32 µs 中约 15 µs 余量。验证：上板观察是否出现横向“陈旧条带”；必要时把取数提前到“行前 1 个整行”（即领先 2 行，需 4 页缓冲）或降低到 30 fps |
| R-06 | 行号锁步漂移：取数引擎（mem 域，靠 `vs_tgl`/`line_tgl` 计数）与显示侧（video 域，靠 vs/de 计数）各自维护行号，若丢一次触发即错页 | 页错位 → 撕裂/花屏 | 两侧均在 vs 边沿清零，且脉冲间隔（32 µs）远大于同步延迟（ns）。验证：把 `fetch_row` 与 `disp_row` 引出上板对比（或加 ILA） |
| R-11 | **顶层改动面较大**（新增仲裁、二选一、5 处 CDC、4 个 BRAM 例化、补齐 `ram_*` 声明） | 可能影响既有显示/字幕/亮度 | 分阶段编译 + 上板回归：每步先过编译，再上板看“不切图时画面正常”“切图有淡入淡出”“字幕/时间戳/亮度正常” |

## 2. 中风险项

| ID | 风险 | 说明 / 缓解 |
|---|---|---|
| R-07 | `disp_buf_idx` 为 2 bit 跨 sd→video 同步 | 仅在帧边界变化、变化后稳定 ≥1 整帧；每位 2-FF 可安全采样。**不**做格雷码转换（现值域小于一个帧周期，实际不会出现中间态被连续采两次） |
| R-08 | 整帧读的 FIFO 欠载（underrun） | 读 FIFO 仅 512 深，若读过早结束会导致像素域读到陈旧数据。既有设计要求读紧贴显示节奏：`S_CHECK_FIFO` 在 `wrusedw >= FIFO_DEPTH-BURST_SIZE` 时停顿，天然把读限制在“最多领先约 256 词”，不会跑飞。**此行为来自既有代码，未改动**；需上板确认整帧读模式下无欠载 |
| R-09 | alpha 混合用 `>>8` 近似 `/255` | 端点精确（alpha=0→old，alpha=256→new），中间最大误差 ±1 LSB（视觉不可见）。若要求严格 `/255`，改动仅限 `xfd_disp_pipe` 内部算式 |
| R-10 | 非转场期间 `video_delay` 仍在推进（`read_en` 常跑） | 转场时读 FIFO 被门控（`we = Sdr_rd_en & ~xfd_en_mem`），`video_delay` 读到的是陈旧数据，但其输出被二选一丢弃，无副作用。此举避免改 `video_delay` 接口 |
| R-12 | 帧缓冲容量 | 3×307200 = 921600 字，片内 SDRAM 为 2 M×32 字（2 097 152），占用 43.9%，余量充足 |

## 3. 低风险 / 已排除

| ID | 项 | 结论 |
|---|---|---|
| R-13 | BRAM 资源 | 4×1024×32 = 4 个 32 Kb 块（共 16 个）；余量充足 |
| R-14 | DSP 资源 | 混合需 3 个 8×9 乘法，29 个 DSP 中占 ≤3 |
| R-15 | 首帧 / 仅 1 张图 / 复位 | 首次加载 `disp` 不变，不触发转场；仅 1 张图不切图；复位后首采样不误触发 |
| R-16 | 转场期间按下“下一张” | `next_req_pending` 会记住请求，转场结束后执行，不丢按键 |
| R-17 | 行缓存的读地址范围 | x ∈ [0,639] < 1024 深度，无越界 |
| R-18 | `rtl/top_skeleton.sv` 是否参与综合 | **不参与**。它是接口参考骨架（含 `blackbox_*` 占位），不在 TD 工程文件列表内；实际编译对象是 `src/user_source/hdl_source/` 下的真实现 |

## 4. 未决问题（需用户在实施前确认）

1. **是否接受 R-01/R-02/R-03 三处偏离**（恢复整帧读、不复制 BUF2、移除 `rd_toggle`）。若坚持“逐行读 + BUF2 复制”，需追加一个 mem 域“行地址生成器”并使复制期冻结黑屏——功能等价但代价更高。
2. **转场时长**：`ALPHA_STEP` 默认 4（≈1.07 s）。如需更短可改 8（≈0.53 s）。此值以参数形式给出，用户可在 RTL 阶段指定。
3. **BUF2 是否留作三缓冲轮换**：本次不用；若要求“写目标永不等于 old”的更强鲁棒性，可在后续把写目标改为第三个缓冲（改动 `sd_card_bmp` 的 `next_buf_lut`）。

## 5. 下游证据要求

- `fpga-rtl-build`：产出 3 个新模块 + 4 处既有文件修改，均无 stub/占位。
- `fpga-compile-and-repair`：对全部改动文件做 `iverilog -tnull` 编译检查（含新增 3 模块、`top_tf_hdmi_audio.v`、`video_timing_data.v`、`sd_card_bmp.v`、`frame_fifo_read.v`）。
- 上板验证清单：①不切图时画面与改前一致；②切图有平滑淡入淡出、无黑屏;③字幕/时间戳/亮度调节/音频均正常；④（可选）引出 `fetch_row`/`disp_row`/`alpha` 观察。
